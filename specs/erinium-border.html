Generation du monde

EriniumBorder

Bande exterieure de plaines neutres autour de la zone pre-generee de l'Overworld. Marque visuellement la fin de la carte explorable sans utiliser le World Border vanilla comme frontiere visuelle.

Statut: implemente Categorie: Monde Version: 1.0 Dimension: Overworld uniquement

01 Contexte & objectif

EriniumFaction pre-genere une portion finie de l'Overworld au demarrage du serveur (par defaut un carre centre sur (0,0) de demi-cote 5 000 blocs). Au-dela, la generation classique de Minecraft continue mais cree des biomes incoherents (chunks generes a la volee par les explorateurs determines, structures partielles, performance degradee).

EriniumBorder resout ce probleme avec une bande de chunks "neutres" placee strictement a l'exterieur de la zone pre-generee. Cette bande sert de frontiere naturelle : des plaines vertes plates, simples, sans mineraux ni structures, qui forment une limite visuelle propre avant que le joueur n'atteigne le World Border vanilla.

  • Plate : terrain uniforme y=63, pas de relief, pas de grottes, pas de minerais.
  • Verte : biome plaines vanilla par defaut (configurable), mobs passifs et hostiles spawn normalement.
  • Stricte : un chunk ne devient JAMAIS un chunk border s'il est dans la zone pre-generee.
  • Reproductible : la commande /eriniumborder regen confirm permet a un admin de reappliquer le template aux chunks border deja charges (apres changement de config par exemple).

02 Geometrie de la bande

La zone pre-generee est definie en blocs dans la config (pre_gen_radius_blocks). Conversion interne en chunks : preGenRadiusBlocks >> 4. Par exemple 5 000 blocs → 312 chunks.

La bande border occupe les chunks dont la distance de Chebyshev (en chunks) au centre (0,0) est comprise entre stripMinChebyshev et stripMaxChebyshev inclus :

stripMinChebyshev = innerChunkRadius + stripInnerChunks (par defaut innerChunkRadius + 1) stripMaxChebyshev = innerChunkRadius + stripOuterChunks (par defaut innerChunkRadius + 2) isBorderChunk(cx, cz) = stripMinChebyshev <= max(|cx|, |cz|) <= stripMaxChebyshev

Avec les defauts (5 000 blocs / 1 chunk inner / 2 chunks outer) : la bande commence au chunk 313 et finit au chunk 314, formant un anneau carre de 2 chunks d'epaisseur autour de la zone pre-gen.

cx = 314 (Chebyshev max) +-------------------------+ | border (outer) | | +---------------------+| | | border (inner) || | | +-----------------+ || | | | pre-gen zone | || | | | (NEVER touched) | || | | | (0,0) | || | | | | || | | +-----------------+ || | +---------------------+| +-------------------------+ cx = 313 (Chebyshev min)
Note : la zone pre-generee est strictement preservee. Tout chunk dont la Chebyshev est < stripMinChebyshev n'est jamais reecrit, meme par /eriniumborder regen.

03 Template de terrain

Quand un chunk border est detecte, son contenu est entierement remplace par un template simple, deterministe et plat :

YBlocQuantite
0Bedrock1 couche (sol absolu)
1 — (surfaceY-5)Stone~58 couches
(surfaceY-4) — (surfaceY-1)Dirt4 couches (sous-couche vanilla feel)
surfaceY (defaut 63)Grass1 couche
surfaceY+1 et au-dessusAirjusqu'a y=255

L'epaisseur de dirt s'aligne sur le comportement vanilla (4 couches de dirt sous le grass). Aucun minerai n'est genere : la couche stone est uniforme. Aucune structure (village, donjon, ruine) n'est populee. Aucun arbre, aucune fleur, aucun mob spawn pendant la population.

Algorithme de remplacement

  1. Recuperer le tableau ExtendedBlockStorage[] du chunk.
  2. Mettre toutes les sections a null (nettoie grottes, minerais, structures partielles).
  3. Re-allouer les sections necessaires (sections 0..surfaceY>>4).
  4. Remplir chaque colonne (lx, lz) selon la regle Y ci-dessus.
  5. Forcer le biomeArray du chunk au biome configure.
  6. Recomputer la skylight, marker lightPopulated et terrainPopulated a true.
  7. Marquer le chunk dirty pour sauvegarde sur disque.
  8. Si l'operation est posterieure a la generation (regen ou ChunkEvent.Load), envoyer un SPacketChunkData aux joueurs traques sur ce chunk.

04 Biome & spawn de mobs

Biome configurable

Le biome utilise dans la bande est defini par border_biome_id (ResourceLocation, par defaut minecraft:plains). Tout biome enregistre est accepte. Le biome est applique :

  • Dans le BiomeProvider : EriniumBiomeProvider.getBiome(BlockPos) retourne le biome border si le chunk est dans la bande. Cela couvre les lookups runtime (lighting, color blending, /locatebiome).
  • Dans le chunk : le biomeArray du chunk est ecrase au biome border lors de l'application du template.

Spawn de mobs

Par defaut (allow_mob_spawn = true), les mobs (passifs et hostiles) spawn normalement dans la bande, exactement comme dans un biome plaines vanilla. C'est le comportement attendu : la frontiere reste un lieu vivant.

Si l'admin met allow_mob_spawn = false, un handler LivingSpawnEvent.CheckSpawn place le resultat a DENY pour tout mob qui tente de spawn dans un chunk border.

07 Commandes admin

Commande : /eriniumborder <info | regen [confirm]>

Permission level : 2 (op uniquement). Auto-completion via getTabCompletions.

/eriniumborder info

Affiche l'etat actuel : statut on/off, rayon pre-gen (blocs et chunks), bornes Chebyshev de la bande, surfaceY, biome ID, allowMobSpawn.

/eriniumborder regen

Premiere invocation sans confirm : affiche un avertissement explicite (operation destructrice qui ecrase tout bloc place par les joueurs dans la bande).

Invocation avec confirm :

  1. Verifier le cooldown global (regen_cooldown_seconds). Si actif : message d'erreur et abandon.
  2. Iterer WorldServer.getChunkProvider().getLoadedChunks().
  3. Pour chaque chunk dont isBorderChunk(cx, cz) == true : appliquer le template.
  4. Afficher le nombre de chunks reecrits + le temps d'execution (ms).
Avertissement : /eriniumborder regen confirm ECRASE tous les blocs places par les joueurs dans la bande (constructions, coffres, etc.). Reserver a une situation de reconfiguration majeure.

08 Performance & cas limites

Cout par chunk

  • Chunks normaux (zone pre-gen ou hors bande) : un seul check Chebyshev en O(1) au PopulateChunkEvent.Pre. Cout negligeable (~1 us par chunk).
  • Chunks border : ecriture complete de ~16 384 blocs (16x16x64). ~5-10 ms par chunk. La bande totale = 4 * (2*innerR + 4) chunks ~ 1 256 chunks pour les defauts. Total cumule lors d'une regen = ~6-12 s.

Memoire

Pre-remplissage des sections via ExtendedBlockStorage.set(). Pas d'allocation supplementaire (les sections etaient deja en RAM cote chunk). Les sections au-dessus de surfaceY sont laissees a null = air = 0 octet stocke.

Cas limites couverts

  • preGenRadiusBlocks = 0 : la bande commence aux chunks 1 et 2. Comportement coherent (anneau autour du spawn).
  • stripInner = stripOuter : bande d'un seul chunk d'epaisseur. OK.
  • Biome ID invalide : fallback sur minecraft:plains (id 1).
  • Chunk deja border rechargee : ChunkEvent.Load verifie la presence du grass a surfaceY ; si absent, repare ; sinon, ne refresh que le biomeArray.
  • Mining World : exclu (dimension != 0). Le mining world conserve son propre terrain.
  • Dimension Erina : exclu egalement (dimension != 0).

09 Plan de tests

  1. Build : gradlew build doit reussir sans erreur. Aucune nouvelle classe Mixin.
  2. Generation : creer un nouveau monde, voler en creatif jusqu'au chunk 313 sur l'axe X. Verifier que le terrain devient plat, herbe a y=63, bedrock a y=0.
  3. Frontiere stricte : verifier que le chunk 312 (dernier chunk pre-gen) garde son terrain original.
  4. Hors bande : voler au-dela du chunk 314. Le terrain doit reprendre le comportement vanilla / custom Erinium.
  5. Biome : /locatebiome plains ou consultation F3 doit retourner minecraft:plains dans la bande.
  6. Mob spawn ON : passer 5 min en survie nocturne dans la bande, verifier que des zombies/squelettes apparaissent.
  7. Mob spawn OFF : changer la config a allow_mob_spawn = false, reload, verifier aucun spawn nocturne pendant 5 min.
  8. Regen sans confirm : /eriniumborder regen doit afficher l'avertissement et n'ecraser aucun chunk.
  9. Regen avec confirm : placer un coffre dans un chunk border, executer /eriniumborder regen confirm, verifier que le coffre est detruit et le terrain remis a plat.
  10. Cooldown : enchainer deux /eriniumborder regen confirm < 30s, verifier le message de cooldown.
  11. Info : /eriniumborder info doit afficher les valeurs config courantes.
  12. Performance : mesurer ms/tick pendant un regen avec 1 200 chunks border charges. Cible : pas de spike au-dela de 100 ms/tick.
