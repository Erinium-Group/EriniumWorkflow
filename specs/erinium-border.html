Generation du monde

EriniumBorder

Bande exterieure de lissage progressif autour de la zone pre-generee de l'Overworld. Effectue une transition douce entre le sol pre-genere et le worldgen naturel, sans creer de mur vertical visible.

Statut: implemente Categorie: Monde Version: 2.0 (smoothing) Dimension: Overworld uniquement

01 Contexte & objectif

EriniumFaction pre-genere une portion finie de l'Overworld au demarrage du serveur. Cette zone est definie par une bounding box arbitraire en blocs (pos1 et pos2, comme dans WorldEdit), par defaut (-500, -500) -> (498, 498) = zone spawn + warzone. Au-dela, la generation classique de Minecraft continue avec son relief naturel (montagnes, oceans, biomes Erinium). La rencontre brutale entre la zone pre-generee (plate, y=63) et le worldgen naturel cree un mur vertical tres visible.

EriniumBorder v2 resout ce probleme avec un lissage progressif sur plusieurs chunks autour de la zone pre-generee. Au lieu d'imposer un terrain plat sur 2 chunks (ce qui deplacait simplement le mur), chaque chunk de la bande interpole sa heightmap entre la baseline (surfaceY=63) cote interieur et la heightmap naturelle du worldgen cote exterieur.

  • Progressive : 5 chunks d'epaisseur par defaut, transition cubique ease-in-out (douce aux extremites).
  • Naturelle : sur les chunks exterieurs de la bande, on garde le biome et les top blocks du worldgen normal (sable du desert, grass des plaines, etc.). Le biome n'est PAS force par defaut.
  • Stricte : un chunk dont la position est dans la bbox pre-gen n'est JAMAIS modifie. La bbox subit un edge chunk shrinkage : si pos1/pos2 ne tombent pas exactement sur un bord de chunk, le chunk concerne est rejete de la zone protegee et devient le premier chunk de la bande de lissage (evite les murs sur le chunk de la pos).
  • Reproductible : la commande /eriniumborder regen confirm reapplique le lissage aux chunks deja charges.

02 Geometrie de la bande

La zone pre-generee est definie en blocs dans la config par quatre cles : pre_gen_pos1_x, pre_gen_pos1_z, pre_gen_pos2_x, pre_gen_pos2_z. Les coordonnees peuvent etre saisies dans n'importe quel ordre : elles sont normalisees en (min, max) a la lecture.

Edge chunk shrinkage

La conversion blocs -> chunks utilise un retrecissement vers l'interieur de la bbox : si la position (en blocs) ne tombe pas exactement sur un bord de chunk, le chunk concerne est retire de la zone protegee et devient le premier chunk de la bande de lissage. Cela evite qu'un chunk soit considere comme pre-gen alors qu'il contient des blocs hors bbox.

// minBlockX inclus dans pre-gen seulement si (minBlockX % 16 == 0) minChunkX = (minBlockX & 15) == 0 ? (minBlockX >> 4) : (minBlockX >> 4) + 1 minChunkZ = (minBlockZ & 15) == 0 ? (minBlockZ >> 4) : (minBlockZ >> 4) + 1 // maxBlockX inclus dans pre-gen seulement si (maxBlockX % 16 == 15) maxChunkX = (maxBlockX & 15) == 15 ? (maxBlockX >> 4) : (maxBlockX >> 4) - 1 maxChunkZ = (maxBlockZ & 15) == 15 ? (maxBlockZ >> 4) : (maxBlockZ >> 4) - 1 isBboxValid = (minChunkX <= maxChunkX) AND (minChunkZ <= maxChunkZ)

Exemple avec les defauts pos1=(-500,-500), pos2=(498,498) :

  • minBlockX = -500. -500 & 15 = 12 (non zero) -> minChunkX = (-500 >> 4) + 1 = -31
  • maxBlockX = 498. 498 & 15 = 2 (non 15) -> maxChunkX = (498 >> 4) - 1 = 30
  • Resultat : bbox pre-gen = chunks [-31,-31] -> [30,30] (62x62 chunks). Les chunks -32 et 31 deviennent les premiers chunks de la bande border.
Si la bbox est trop petite et que le shrinkage la rend invalide (minChunk > maxChunk), le systeme se desactive a l'execution avec une erreur claire au demarrage. La bbox doit couvrir au moins 1 chunk plein (16 blocs alignes sur la grille des chunks).

Distance & bande

La bande border occupe les chunks dont la distance de Chebyshev en chunks au rectangle pre-gen est comprise entre 1 et smoothing_width_chunks inclus. La distance vaut 0 si le chunk est dans la bbox (jamais touche).

dx = max(minCX - cx, cx - maxCX, 0) dz = max(minCZ - cz, cz - maxCZ, 0) distance(cx, cz) = max(dx, dz) isPreGenChunk(cx, cz) = (distance == 0) isBorderChunk(cx, cz) = (1 <= distance <= smoothing_width_chunks)
distance = 5 (smoothing_width_chunks) +-----------------------------+ | border d=5 (t=1.0, naturel) | | +-------------------------+| | | border d=4 (t~0.75) || | | +---------------------+|| | | | border d=3 (t~0.5) ||| | | | +-----------------+||| | | | | border d=2 (t~0.25)| | | | | +-------------+ ||| | | | | |border d=1 | ||| | | | | |(t=0, plat) | ||| | | | | | +---------+ | ||| | | | | | |pre-gen | | ||| | | | | | |(jamais | | ||| | | | | | |touche) | | ||| | | | | | +---------+ | ||| | | | | +-------------+ ||| | | | +-----------------+||| | | +---------------------+|| | +-------------------------+| +-----------------------------+
Note : la zone pre-generee est strictement preservee. Tout chunk dont la distance Chebyshev a la bbox est 0 n'est jamais reecrit, meme par /eriniumborder regen. La bbox n'a pas besoin d'etre centree sur (0,0).

03 Lissage progressif (smoothing v2)

Le worldgen genere le chunk normalement (terrain + structures + decorations). Apres population, EriniumBorder intervient pour blender la heightmap de chaque colonne entre une baseline plate cote interieur et la hauteur naturelle cote exterieur.

Facteur d'interpolation

Pour un chunk a la distance Chebyshev d de la bbox (1 <= d <= smoothing_width_chunks) :

tChunk = (d - 1) / (smoothing_width_chunks - 1) // [0, 1] eased = easeInOutCubic(tChunk) // Pour chaque colonne (lx, lz) du chunk : hNatural = scan top-down [255..1] -> premier bloc solide (ignore air, leaves, logs, fleurs, neige...) hTarget = round(lerp(surfaceY, hNatural, eased))
  • d=1 : t=0 -> hTarget=surfaceY (terrain plat au niveau baseline)
  • d=smoothing_width_chunks : t=1 -> hTarget=hNatural (terrain naturel preserve)
  • Entre les deux : transition cubique douce (ease-in-out)

Application par colonne

Trois cas selon la comparaison hTarget vs hNatural :

CasAction
hTarget < hNatural (abaisser)Air de hTarget+1 a hNatural. Grass a hTarget. 3 dirt sous. Nettoie aussi les decorations (arbres, neige, plantes) jusqu'a hNatural+24.
hTarget > hNatural (rehausser)Stone de hNatural+1 a hTarget-1. Grass a hTarget. 3 dirt sous (uniquement la ou c'etait stone). Nettoie les decorations au-dessus de hNatural.
hTarget == hNaturalColonne laissee intacte. Garde tout : top blocks naturels, arbres, fleurs, structures. C'est le cas du bord exterieur de la bande (t ~ 1).

Detection de la hauteur naturelle

Le scan top-down ignore les blocs qui ne representent pas le terrain solide : air, feuilles, troncs, herbes hautes, fleurs (jaune/rouge), champignons (et leurs blocs geants), couches de neige, nenuphars, vignes, cactus, canne a sucre, deadbush, citrouilles, pasteques. Le premier bloc qui n'est pas dans cette liste est considere comme la surface naturelle.

Hook Forge

  1. PopulateChunkEvent.Post avec priority = LOWEST : on attend que tout le worldgen normal (terrain + structures + decorations) ait fini.
  2. Skip si chunk hors bande ou hors Overworld.
  3. Calcul de tChunk et eased une fois par chunk.
  4. Pour chaque colonne (256 colonnes/chunk) : scan hNatural, calcul hTarget, application des blocs.
  5. Override biome optionnel UNIQUEMENT si border_biome_id est non vide.
  6. Regen skylight, mark dirty, repush SPacketChunkData aux clients trackant le chunk.
Performance : 256 colonnes/chunk, chacune avec un scan top-down O(256) et un rewrite O(64). Cout total par chunk ~5-15 ms. Comme la generation de chunk n'est pas un hot path tick (rare evenement), c'est invisible meme avec 500-1000 joueurs.

04 Biome & spawn de mobs

Biome naturel par defaut (v2)

En v2, le biome n'est PAS force dans la bande border. Le worldgen attribue ses biomes Erinium naturels et nous gardons ces biomes intacts. Le lissage modifie la heightmap mais conserve les top blocks adaptes au biome local (grass plaines, sable desert, etc.). Cela garantit une transition visuelle continue : pas de "ligne" entre les biomes Erinium et la bande de lissage.

Override optionnel

L'admin peut forcer un biome via border_biome_id (ResourceLocation, par defaut "" = vide = pas d'override). Si non vide, le biome est applique a la fois :

  • Dans le BiomeProvider : EriniumBiomeProvider.getBiome(BlockPos) retourne le biome configure si le chunk est dans la bande.
  • Dans le chunk : le biomeArray du chunk est ecrase au biome configure lors de l'application du lissage.

Spawn de mobs

Par defaut (allow_mob_spawn = true), les mobs (passifs et hostiles) spawn normalement dans la bande, en suivant les regles du biome naturel sous-jacent. C'est le comportement attendu : la frontiere reste un lieu vivant.

Si l'admin met allow_mob_spawn = false, un handler LivingSpawnEvent.CheckSpawn place le resultat a DENY pour tout mob qui tente de spawn dans un chunk border.

07 Commandes admin

Commande : /eriniumborder <info | regen [confirm]>

Permission level : 2 (op uniquement). Auto-completion via getTabCompletions.

/eriniumborder info

Affiche l'etat actuel : statut on/off, bbox pre-gen (blocs et chunks normalises min/max), bornes de distance de la bande, surfaceY, biome ID, allowMobSpawn.

/eriniumborder regen (force-load batche)

Premiere invocation sans confirm : affiche un avertissement explicite (operation destructrice qui ecrase tout bloc place par les joueurs dans la bande).

Invocation avec confirm :

  1. Verifier le cooldown global (regen_cooldown_seconds) et qu'aucun regen n'est deja en cours. Si actif : message d'erreur et abandon.
  2. Enumerer tous les chunks de la bande (Chebyshev 1..smoothing_width_chunks), pas seulement les chunks deja charges.
  3. Snapshot des chunks deja charges (pour les preserver loaded apres regen).
  4. Hook TickEvent.ServerTickEvent phase END : a chaque tick, traiter jusqu'a regen_chunks_per_tick chunks :
    • ChunkProviderServer.loadChunk(cx, cz) = force-load depuis disque ou genere si manquant.
    • Appliquer le lissage column-par-column.
    • chunk.markDirty().
    • Si le chunk n'etait pas loaded au debut du regen : cps.queueUnload(chunk) pour eviter une explosion RAM.
  5. Messages de progression (10%, 20%, ..., 100%) en console et au sender de la commande.
  6. A la fin de la queue : world.saveAllChunks(true, null) pour flush sur disque, message recap.
Performance : avec regen_chunks_per_tick=20, une bande de 5 chunks autour de la bbox par defaut (~1340 chunks) prend ~67 ticks soit ~3.5s. Le pic TPS est borne (~20 chunks de smoothing par tick = ~100-300 ms total etale).
Avertissement : /eriniumborder regen confirm ECRASE tous les blocs places par les joueurs dans la bande (constructions, coffres, etc.). Reserver a une situation de reconfiguration majeure.

08 Performance & cas limites

Cout par chunk

  • Chunks normaux (zone pre-gen ou hors bande) : un seul check Chebyshev en O(1) au PopulateChunkEvent.Post. Cout negligeable (~1 us par chunk).
  • Chunks border : 256 colonnes scannees top-down (O(256)) + rewrite par colonne O(64). Cout total ~5-15 ms par chunk. Pour la bbox par defaut (62x62 chunks apres shrinkage) avec une bande de 5 chunks, ~700 chunks border au total. Regen complet = ~3-10 s (event ponctuel, non bloquant pour le tick principal).

Memoire

Aucune allocation persistante. Les modifications sont des set in-place sur les ExtendedBlockStorage existants du chunk. Les sections vides restent null = air = 0 octet.

Cas limites couverts

  • pos1 == pos2 : un seul bloc, donc bbox vide apres shrinkage => bbox invalide, systeme desactive avec erreur explicite.
  • pos1 et pos2 inverses : la normalisation min/max gere le cas.
  • bbox decentree : aucun probleme, la distance Chebyshev est independante du centre.
  • bbox trop petite : si la zone est plus petite qu'un chunk plein apres edge shrinkage, le systeme se desactive automatiquement avec un log erreur clair (isBboxValid() = false).
  • pos sur bord exact de chunk : si minBlockX % 16 == 0 (resp. maxBlockX % 16 == 15), le chunk est inclus dans le pre-gen (pas de shrinkage cote concerne).
  • Biome ID vide : pas d'override, biomes naturels conserves (cas par defaut).
  • Biome ID invalide : fallback silencieux, pas d'override applique.
  • smoothing_width_chunks = 1 : bande d'un chunk d'epaisseur a t=0 (terrain plat strict, comportement v1 sur ce chunk uniquement).
  • Chunk deja populated rechargee : ChunkEvent.Load est no-op. Le lissage est persistant sur disque.
  • Mining World / Dimension Erina : exclu (dimension != 0).

09 Plan de tests

  1. Build : gradlew build doit reussir sans erreur. Aucune nouvelle classe Mixin.
  2. Edge shrinkage : avec defaut pos1=(-500,-500) pos2=(498,498), /eriniumborder info doit afficher chunks pre-gen [-31,-31] -> [30,30] (pas [-32,-32] -> [31,31]).
  3. Pas de mur sur chunk de la pos : voler en creatif sur le chunk -32 (qui contient le bloc x=-500). Le terrain doit etre lisse (premier chunk de la bande, t=0), pas avoir un mur a la frontiere x=-500.
  4. Transition douce : voler depuis l'interieur de la zone pre-gen vers l'exterieur. La hauteur du sol doit augmenter/descendre progressivement sur 5 chunks (~80 blocs) jusqu'a rejoindre la heightmap naturelle. Aucun mur vertical visible.
  5. Biomes naturels preserves : F3 dans la bande doit afficher des biomes Erinium (forets, plaines, etc.), pas minecraft:plains (sauf si override force).
  6. Frontiere stricte : chunks au coeur de la zone pre-gen (loin du bord) intacts.
  7. Hors bande : voler au-dela du chunk 35. Le terrain doit etre 100% worldgen naturel (montagnes, arbres, biomes Erinium).
  8. Mob spawn ON : 5 min en survie nocturne dans la bande, verifier que des mobs apparaissent normalement selon le biome local.
  9. Mob spawn OFF : config allow_mob_spawn = false, reload, verifier aucun spawn pendant 5 min dans la bande.
  10. Override biome optionnel : mettre border_biome_id = minecraft:plains, regen, verifier que F3 affiche plains dans la bande.
  11. bbox invalide : mettre pos1=(0,0) pos2=(5,5), redemarrer. Le log doit montrer une erreur "bbox invalide", le systeme doit etre desactive a l'execution.
  12. Regen sans confirm : /eriniumborder regen doit afficher l'avertissement.
  13. Regen avec confirm : placer un bloc dans un chunk border, executer /eriniumborder regen confirm, verifier que le terrain est relisse.
  14. Cooldown : enchainer deux regen < 30s, verifier le message de cooldown.
  15. Info : /eriniumborder info affiche width, surface_y, override biome, bbox valid.
  16. Performance : mesurer ms/tick pendant un regen avec ~700 chunks border charges. Cible : aucun spike > 100 ms/tick.
